WNBA Analytics Audit Report
CRITICAL ISSUES 🔴
1. Defensive Metrics Merge Logic is Broken
File: defensive_metrics.py (lines 24-29)

Problem: The merge requires BOTH game_id AND opponent to match, but the structure creates a logical impossibility:

DataFrame df has columns: game_id, team, opponent
DataFrame opponent_df is renamed to have: game_id, opponent (renamed from team)
Merge condition: on=["game_id", "opponent"]
Result: Trying to match df.opponent with opponent_df.opponent (which is actually the opposite team)
Impact: All opponent stats will be NaN/missing. Any analysis using opp_offensive_rating, opp_shot_value, etc. is calculating on empty data.

Fix Required: Rename opponent_df team column to something else, or restructure the merge entirely.

2. Critical Division-by-Zero Issues Not Fully Handled
File: clean_player_data.py (lines 19-21)

Problems:

player_offensive_flow = ast / fgm - fails when FGM = 0 (bench players, 0-pt games)
assist_turnover_ratio = ast / to - fails when TO = 0 (no turnovers is actually good, should not be NaN)
Script replaces infinity with NaN, but this creates SILENT DATA LOSS
No warning that 5-40% of player records may be NaN for these metrics
Similar Issue in: advanced_metrics.py line 24

offensive_flow = ast / fgm
assist_turnover_ratio = ast / to
Impact: Users see incomplete player profiles without realizing it's data quality issue.

3. Inconsistent File Paths & Missing Column Validation
File: Multiple (analyzed 5+ scripts)

Problems:

advanced_metrics.py reads from ../data/full_wnba_team_stats.csv - no error handling if missing
defensive_metrics.py reads from ../outputs/advanced_wnba_metrics.csv - assumes it exists
team_style_classifications.py reads ../outputs/defensive_metrics.csv - depends on broken merge
No validation that required columns exist before operations
Example: If offensive_rating column is missing, all thresholds fail silently.

Impact: One missing file breaks entire downstream pipeline with cryptic errors.

4. Name Matching is Unsafe for API Users
File: lineup_ecosystem_engine.py, matchup_engine.py, player_matchup_engine.py

Problem: Functions like name_matches() use string fuzzy matching:

if "." in input_name:
    input_initial = input_parts[0].replace(".", "").lower()
    input_last = input_parts[-1].lower()
    return (
        full_parts[0].lower().startswith(input_initial)
        and full_parts[-1].lower() == input_last
    )

Issues:

"A. Thomas" could match both "Alyssa Thomas" AND "Angel Thomas"
Typos like "Allyssa" won't match "Alyssa"
No penalty for multiple matches
No API returns "did you mean?" suggestions
Impact: Frontend users get wrong player data with no feedback.

5. Defensive Metrics Conceptually Flawed
File: defensive_metrics.py (lines 29-42)

Current Logic:

df["defensive_pressure"] = 1 - df["opp_ball_security"]
df["opponent_offensive_rating_allowed"] = df["opp_offensive_rating"]

Problem:

defensive_pressure = 1 - opp_ball_security is circular logic
"Opponent's ball security" isn't really a defensive stat - it's opponent's turnover rate
opponent_offensive_rating_allowed is just copying opponent's own ORating (confuses offensive performance with defensive impact)
Basketball Concept: Defensive metrics should show what defense allows, not what offense produced. This is inverted.

Example: If Team A scores 120 ORating against Team B, the values get:

Team B's opponent_offensive_rating_allowed = 120 [PASS] Correct
But Team B's defensive_pressure = 1 - 0.92 = 0.08 [FAIL] This is backwards
Impact: Defensive analysis is unreliable. Users can't distinguish "good defense" from "playing vs poor offense."
